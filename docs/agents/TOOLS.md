# Agent 工具箱清點（程式輔助 × 各角色）

> **用途**：盤點各角色除了 **Gemini prompt** 之外，可搭配哪些**程式碼、腳本、小服務**完成工作；方便之後在私有環境實作、或由人手工執行同一邏輯。  
> **編輯方式**：狀態欄填 `規劃中`／`已有`／`暫不實作`；實作路徑可指向本 repo 內 `scripts/`（若你日後新增）或另開私有 repo。

---

## 政策提醒（可刪改）

- 審核中內容**不**應因工具流程而進入**公開** repo／公開 PR（依總編輯政策調整此段）。
- 工具**不得**自動發布至正式站、**不得**自動 merge 公開分支（若日後開放，請改寫並註明條件）。
- 涉及個資、在世家屬、爭議敘述時，預設**標記待人工**，不替總編輯做最終定論。
- 對外抓取 URL、呼叫地理 API 時，注意頻率、robots、與資料存放位置（**私有**為宜）。

---

## 常見實作問題：投稿網址、檔案館 API、UI 與本專案

### 投稿只有網址，Gemini 未必能「開網頁」時

- **不必**先寫一個「假裝是 Chrome」的完整瀏覽器。多數情況用 **HTTP 程式**（Node `fetch`、Python `requests` 等）做 **HEAD／GET**，取回狀態碼、轉址後網址、`Content-Type`、必要時取 `<title>` 或**節錄正文**，再把這段**文字結果貼給 Gemini** 當 §3 的輸入即可。這對應工具 **T03**。
- **動態網頁**（大量 JavaScript 才出內容）才考慮 **Playwright／Puppeteer** 等「無頭瀏覽器」——較重、較慢，建議列為**選用**，且注意資源與站方條款。
- **PDF／圖片**連結：不要當成一般 HTML 硬解；可標記 `needs_human` 或另用 PDF 文字抽取工具（再視授權與需求決定是否實作）。

### 國家檔案館／國家人權館等資料庫，若之後有 API 或可查詢介面

- **若官方提供 API 或可結構化查詢**：值得寫一支**薄包裝**（小腳本或 serverless），把查詢參數與回傳 JSON **正規化**後再餵給 §3 或 PM；金鑰放環境變數，**不要**進公開 repo。可在工具登錄新增一筆（例如 **T22 `archive_nhrm_search`**），找到文件後再填端點與欄位對照。
- **若僅有網頁查詢、無 API**：實務上仍是「人查／或 T03 取頁再節錄」為主，不必為了「像 API」硬爬，避免違反使用條款。

### UI 工程師要不要「把網頁框架 copy 一份」？

- **不建議**為了預覽而把整站 **copy 到另一個專案**維護兩份 React——日後一改版型就要改兩次。
- **建議**：在**同一個 repo** 內，用 **dev-only／私有分支** 加一條「編輯預覽」路由（例如只在本機或密鑰保護的 preview 環境開），**直接 import** 現有 `StorySidebar`、`MapView`、型別與樣式；資料來自審核包 JSON 或暫存檔。這對應 **T13、T14**。
- 若短期內只想驗證文案，也可讓 §7 產出**單一 HTML 檔**對照版型（維護成本較高，適合過渡）。

## 角色 ↔ 建議程式工具（總覽）

下列代號與下一節「工具登錄」對齊；**同一工具可被多個角色共用**。

| 角色 | 建議搭配的工具代號 | 說明（一句） |
|------|-------------------|--------------|
| **PM** | T10, T11, T12 | 彙整多段 agent 輸出、校驗審核包欄位、比對多輪 `round` |
| **§2 資料結構化** | T01, T02 | 讀取投稿 JSON、轉後台主表（Markdown／列）、schema 基本檢查 |
| **§3 台灣歷史資料學** | T03, T04, T05, （待補 T22 檔案館 API） | 連結 HEAD/中繼資料、網域分類、與既有 `stories` 摘要比對；日後可加官方資料庫查詢包裝 |
| **§4 文字編輯** | T06 | 字數／段落檢查（可選，不取代人工判斷） |
| **§5 地理資訊** | T07, T08 | 地理編碼、座標是否合理（範圍台灣）、產生地圖測試用標記 |
| **§6 權益／法務** | T09 | 僅輔助：關鍵字／樣式標記「需人工覆核」（**不可**當自動審查） |
| **§7 UI 工程師** | T13, T14, T15 | 將故事 JSON 注入預覽路由、產生 TSX 骨架、本機預覽指令 |

**共用／基礎建設**（不限單一角色）：讀寫私有審核目錄、環境變數、log、Gemini API 呼叫包裝等——見下方 T20 起。

### T22 — `nhrm_archive_agent`（本地 NHRM 查詢）

| 欄位 | 內容 |
|------|------|
| **給誰用** | §3、PM |
| **能力說明** | 以 Gemini function calling 查詢本地 `nhrm_merged.json`（12,060 筆），無需連網。支援姓名搜尋、nhrm_id 取完整資料、案件名稱搜尋、同案人物查詢。 |
| **輸入** | 自然語言問題（互動或 `--ask`）、或直接 import 呼叫工具函式 |
| **輸出** | 自然語言回答（含引用具體資料）；工具函式直接回 JSON |
| **實作路徑** | [`scripts/agents/nhrm_archive_agent.py`](../../scripts/agents/nhrm_archive_agent.py) |
| **資料來源** | `data/processed/nhrm_merged.json`（需先執行 `scripts/tools/merge_nhrm.py`） |

**狀態**：已有

工具函式（可直接 import 使用）：
- `tool_search_by_name(name, exact=False)` → 摘要清單
- `tool_get_person(nhrm_id)` → 完整資料
- `tool_search_by_case(case_name)` → 涉案人員清單
- `tool_get_related_persons(nhrm_id)` → 同案人物清單
